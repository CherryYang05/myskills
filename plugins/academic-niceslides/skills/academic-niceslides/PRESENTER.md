# academic_niceslides · 学术报告导演法

所有风格共用这一份。它决定质感的下限；`styles/<slug>/STYLE.md` 只决定“像什么”。
读法：先读本文，再读一份 STYLE.md，然后才动手。

## 0. 为什么之前的模板还是有 AI 味

1. **风格被做成了皮肤。** 同一副骨架换配色和字体，缩略图上只是“换了个颜色的同一页”。
   好的风格是一种**媒介**（印刷的专著、瑞士海报、工程图纸、孔版印刷），页面上每个决定都能从媒介推出来。
2. **强调靠“离群值”。** 开头极短的小标题、超大数字，都是在没有构图的时候用尺寸和标签硬造层级。
   层级只允许来自三样：**位置、粗细、系列色**。字号不是强调手段。
3. **质量靠事后检查。** 检查什么，agent 就优化什么，没检查到的照样出 slop。
   所以先让 slop **写不出来**（IR 里没有那个字段），再检查剩下的。

## 1. 判断顺序

论证 → 证据 → 构图 → 质感。前一项没立住，后一项做得再好也不算数。

### 默认七段式学术结构

除作者另有要求外，正片（扉页之后）按以下七部分组织叙事，并映射到现有 `deck.json` 版式（`title`、`flow`、`fig`、`models`、`paperfig`、`close`；不要自行新增版式名）：

1. **研究问题（RQ）**：核心问题与研究动机（`flow` 或 `paperfig`）。
2. **文献缺口（Gap in Literature）**：已有研究共识与尚未解决的缺口（`flow` 或论文对比/综述原图 `paperfig`）。
3. **理论与假设（Theory and Hypotheses）**：理论机制、概念框架与可检验假设（`flow` 或论文机制示意图 `paperfig`）。
4. **数据与方法（Data and Methods）**：数据来源、样本、识别策略或实验/实证设计与估计方法（`flow`、`paperfig` 或 `fig`）。
5. **核心发现（Core Findings, detail）**：报告主干，按需拆成多页详述主发现、核心图表/模型、异质性或机制与稳健性检验（`fig`、`models`、`paperfig`，所有数字均来自 `facts.json`）。
6. **研究贡献（Contribution）**：理论、实证或方法上的核心贡献（`flow` 或 `close`）。
7. **局限与未来研究（Limitations / Future Study）**：主要局限、边界条件与后续方向（`flow`，或合并入收尾 `close` 页并附文献与论文二维码）。

注：七个章节名写在 `meta.sections`（供页脚/侧栏导航）里，每页 `title` 仍必须是断言式整句（≥ 6 词、≤ 2 行、不以冒号结尾）。若选用 `rail` 或 `chapter`（导航栏/底色更适合 ≤ 6 个章节），可在 `meta.sections` 中将相邻标签简写合并（如“RQ & Gap”“贡献与局限”），但正文页面仍完整保留七部分内容。

## 2. IR：只有语义，没有装饰位

项目目录里的 `deck.json` 是唯一的源头：agent 写它，编辑器改它，所有输出从它生成。一页只能有：

| 字段 | 含义 | 约束 |
|---|---|---|
| `title` | 断言式整句 | ≥ 6 词，≤ 2 行，不以冒号结尾 |
| `chart` / `steps` / `points` / `table` / `figure` | 这一页的唯一主视觉 | 一页一个；图表由登记数据用代码画，`figure` 是论文原图 |
| `notes` / `caption` / `note` | 完整句子 | 每块 ≥ 5 词 |
| `section` | 页脚里的章节名 | 只出现在页脚 |

**不存在的字段**：眉题（kicker）、大数字（stat callout）、卡片、图标栅格、标签条。
想加这些，等于改 schema，需要先说明它编码了什么信息。

标记只有三种：`{fact_id}` 引用登记数字；`[a|…]` `[b|…]` 把一个词绑到数据系列；`[c|…]` 文献。

## 3. 数字

- 正文里不许直接写数字。每个数字都是 `{fact_id}`，来自项目里的 `facts.json`，由项目的 `analysis.py` 从原始数据算出。
  引用未登记的 id，构建直接失败。
- 数字和它所在的句子**同字号**。要强调就加粗或用系列色，不放大。
- 推导量（置信区间、对比差）在 `facts.json` 的 `how` 里写清算法，页面图注里用一句话交代。
- 标题不能比证据说得更满。交互项不显著，标题就写“太不精确，无法确认”。

## 4. 字阶（全库固定，单位 px，画布 1920×1080，1pt = 2px）

| 角色 | 字号 | 备注 |
|---|---|---|
| 标题 | 56–62 | 风格在此范围内取值 |
| 正文 | 36 | |
| 次级正文、表格 | 30–32 | |
| 图注、页脚、图内文字 | 28 | **全页下限 = 14pt** |
| 扉页标题 | 88–132 | 只有扉页可以超过标题字号 |

一种风格一个字体家族，全稿不换。

## 5. 构图

- 12 栏网格，栏距 32，左右边距 120。所有风格共用。
- 图占 8 栏、文字占 4 栏是默认；风格可以镜像或改位置，不能改栏宽体系。
- 标题与主体之间的那条线（或留白）是全稿的“挂线”，位置逐页不变。
- **识别锚点来自内容**（`META["anchor"]`）：论文里的一张图、一个装置、一个示意。样张用的是“两份只差名字的简历”，出现在扉页、设计页、结论页。不用吉祥物，不用库存图。
- 同一个系列在标题、图、表里永远同色。读者不需要图例。

## 6. 图表文法

- 直接标注，不用图例。数值标签 32px。
- 柱从零起。区间一律画出来，并在图注写明是什么区间。
- 差值用尺寸线标出（“相差 3.2 个百分点”），不靠读者目测。
- 图按槽位 1:1 绘制，不缩放，所以图内字号就是页面字号。
- 风格只能通过 CSS 类改“笔触”（实心、空心、网点、剖面线），不能改几何和数据。

## 7. 逐步呈现

学术报告里“先出两组，再出差值，最后出显著性”是论证顺序，不是特效。所以只声明顺序：

- 任何元素都可以写 `"at": n`，表示第 n 次点击时出现（0 = 随页面出现）。图里的柱、线、行，表里的行，正文段落，都一样。
- `gap`（尺寸线标差值）和 `sig`（括线加检验结果）是柱图自带的两种标注，各自可以带 `at`。星号和 p 值必须来自登记的检验。
- 隐藏的元素照样占位。元素出现时，页面上其他东西一个像素都不动。
- 唯一的“动”是论文原图的放大（见第 9 节）。没有飞入、旋转、弹跳。
- 一页最多 4 次点击。超过就拆页。
- 可选字段：`meta.author` 和 `meta.email` 显示在每一页页脚；每页的 `say` 是讲稿；`meta.link` 会在结论页生成指向论文的二维码；`meta.cite` 是完整出处。
- 同一份源文件三种输出：放映（点击或方向键逐步）、`#flat`（每页终态，给 lint 和缩略图）、`#expand`（每次点击一页，给 PDF，等同 Beamer 的 overlay）。

## 8. Logo

- 在 `META["logos"]` 里登记文件；深色风格用 `dark` 指向反白版本。
- 只出现在两处：扉页（最高 96px）和页脚左端（只放第一个，最高 48px）。
- 不变形、不改色、不加底板。lint 检查位置、高度和宽高比。
- logo 是署名，不是装饰。内容页不允许再出现第二处。

## 9. 论文里的图和表

原则：**原图不重画**。重画就得重新保证每个数字，那是图表引擎的事，不是原图的事。

- 用 `engine/extract.py` 从 PDF 按页码和坐标取图（300 dpi），同时写入 `assets/provenance.json`（PDF 指纹、页码、坐标、最小字号）。
- 允许三种操作，都在 `figure` 里声明：
  - `crop`：只留要讲的部分；
  - `cover`：遮掉不讲的格子或图例；
  - `focus`：先标出一格，下一次点击放大到这一格。
- 图注必须说明做了什么（“原图上排，未改动；质量一格此处略去”），来源由引擎自动追加。
- 可读性：原图里最小的字，在终态下不得小于 24px（12pt）。达不到就继续裁切或放大；还达不到，就用登记数据重画成原生图表，并在图注注明“据原文表 X 重绘”。
- 表格同理：要么当作图片走上面的流程，要么把要讲的行列登记成 fact 后用 `table` 重排，图注写明是节选。
- 禁止：拉伸、改色、擦除数据点、AI 生成或“美化”原图。

## 10. 流程

1. **确认与取证**：若用户未指定风格，主动列出全部 17 种风格名称并附仓库预览链接供选择；同时确认是否遵循默认七段式结构以及各部分有无特殊要求（无特殊要求则直接推进）。确认后，用项目的 `analysis.py` 把全部数字算进 `facts.json`，原图用 `extract.py` 取出。
2. **Storyboard**：按已确认的结构（默认七段式，并详述 Core Findings）写 `deck.json` 的断言式标题、证据映射和点击顺序；若用户要求先审标题，先发清单等待确认。
3. **选风格 / 构建**：按用户选定风格执行 `python3 engine/build.py <project> --styles <slug>` → `out/deck.html`。仅当用户仍希望在自己的内容上横向比对，或无人值守未指定风格时，先用 `python3 engine/build.py <project> --open gallery` 产出全风格画廊供挑选。
4. **Lint**：`python3 engine/lint.py <project>`，必须全过。
5. **目检**：`python3 engine/render.py <project> <slug>`，看 `out/sheets/`（终态）和 `out/steps/`（每次点击），修一轮。
6. **交付**：`out/deck.html`（放映、编辑、导出都在这一个文件里）、`out/<slug>.pdf`、需要时 `out/<slug>.pptx`。

## 11. Lint 规则（对渲染后的页面跑，不是对源码跑）

| 规则 | 检查 |
|---|---|
| `min-size` | 任何文字 < 28px（14pt） |
| `giant` | 内容页上任何文字大于标题 |
| `stat-callout` | 数字比它所在的句子大 |
| `eyebrow` | 标题上方出现任何文字 |
| `fragment` | 少于 5 词的独立文字块 |
| `assertion` / `title-lines` | 标题不是整句，或超过 2 行 |
| `one-family` | 一页出现第二种字体 |
| `provenance` | 页面上出现没有登记来源的数字 |
| `overflow` / `overlap` / `label-collision` | 出界、压叠、图内标签相撞 |
| `contrast` | 文字对比度不足 |
| `step-gap` | 某次点击没有任何元素出现 |
| `logo-place` / `logo-size` / `logo-stretch` | logo 位置、高度、宽高比 |
| `figure-credit` / `figure-legible` | 原图没有来源，或终态下字太小 |

## 12. 交付之后怎么微调

成品 `deck.html` 自带编辑器（放映时按 E，或从画廊点“编辑这份幻灯片”）。原则只有一条：
**每次改动都写回 deck.json 再重新渲染，页面永远不是源头**。所以改完仍然通过同一套 lint，换风格也不丢改动。

编辑方式和 Slides 一样：**点页面上的东西，旁边弹出它自己的工具条**。右侧面板放不常用的设置。

| 点什么 | 能做什么 |
|---|---|
| 任何一段文字 | 直接打字。工具条：加粗、对照系列色、焦点系列色、强调色（色块旁的小箭头改全稿强调色）、次要灰、清除格式、插入数字 |
| 列表里的一段（正文、步骤、结论） | 另有 ↑ ↓ 移动、＋ 在下面加一段、⧉ 复制、✕ 删除 |
| 图表里的标签、表头、表格行名 | 弹出一个输入框；多行标签用 “ / ” 分行 |
| 图表空白处 | 版式工具条：⇄ 图文对调、图 − / 图 ＋（按栏变宽变窄）、文字靠上 / 居中 / 靠下 |
| 图和文字之间的竖条 | 左右拖动，按 12 栏网格吸附 |
| 页脚或扉页的 logo | 换一张图片、加深色背景用的版本、放到最前、再加一个、删除 |
| 贯穿全稿的示意图 | 换成自己的图片、改用论文里的某张图、恢复样张示意图、不显示 |
| 论文原图 | 裁切与放大（拖框）、换一张图片、填原图最小字高 |

右侧面板：出现顺序（每个元素在第几次点击出现）、署名与标识（页脚短标题、讲者、邮箱、完整出处、论文链接、logo 列表）、版式、风格与两组数据的颜色、讲稿、本页全部字段（坐标范围、刻度等）、检查。
左侧列表：切页、上移下移、复制、删除整页。快捷键：⌘/Ctrl+Z 撤销，⌘/Ctrl+Shift+Z 重做，↑ ↓ 切页，Esc 收起工具条。

为什么颜色只给五种、位置只能按栏挪：这样改完的页面仍然对齐、仍然通过检查，换风格时改动也跟着走。
颜色不是写死的色值，而是“这段话属于哪一组数据”；换成另一种风格，同一个词会自动换成那个风格里那一组的颜色。

上传的图片（logo、示意图、替换的原图）会存进 HTML，也会随“导出 deck.json”一起导出；
把这个 deck.json 放回项目再运行 `build.py`，图片会自动解包到 `assets/uploads/`。

保存有三种：存成新的 HTML（自带一切，可以直接发给合作者继续改）、导出 `deck.json`（交还给 agent 或用来导出 PPTX）、复制 JSON。

放映时的按键：→ 下一步，← 上一步，F 全屏，N 讲稿，D 显示本页每个数字是怎么算出来的，S 换风格，E 编辑，G 画廊。

## 13. PowerPoint

`python3 engine/export_pptx.py <project> --style <slug>` 写出 `out/<slug>.pptx`：

- 所有文字是原生文本框，字体、字号、颜色、加粗都在，可以直接改；
- 图表、形状、原图是图片，垫在文字下面，不能在 PowerPoint 里改数据；
- 逐步呈现是原生的“单击时出现”动画；加 `--pages` 则改成每次点击一页；
- logo 和示意图是单独的图片，名字是 Logo 1、Anchor image，右键“更改图片”就能换；
- 讲稿进备注页；`out/fonts/` 里是这套风格的字体，打开前先装上，否则会被替换成别的字体。

这是单向出口。在 PowerPoint 里的改动回不到 `deck.json`，重新生成会丢。
要长期维护的改动在编辑器里做；PowerPoint 留给必须交 .pptx 的场合，或者往里插自己另做的页。

## 14. 最常见的失败

- 标题是名词短语（“实验结果”）。改成结论。
- 为了“精美”缩小字号塞更多内容。删内容，不缩字。
- 给图加第二种强调色。一页只有一个焦点系列。
- 每个要点都设一次点击。点击只留给论证的转折。
- 把整页论文图直接贴上去。先问这一页要讲的是哪一格。

## 15. 加一种新风格

复制 `styles/_template/`，按 STYLE.md 的九节写完再写 CSS，字体文件放进 `fonts/`。
风格可以用的钩子：`data-sec`（章节序号）、`.secnav`（章节列表）、`.citeline`（完整出处）、`.fp`（数据指纹）、`.prog b`（每页一个进度节点），默认都不显示。
验收：联系表缩到 480px 宽，能一眼和已有风格分开；lint 全过；不改 `base.css` 和 `charts.py`。
