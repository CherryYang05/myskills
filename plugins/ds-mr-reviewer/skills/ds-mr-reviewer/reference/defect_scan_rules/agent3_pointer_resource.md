# 缺陷模式检测规则库 - Agent 3: 指针操作类 + 资源管理类

## 扫描范围与原则

- 聚焦于 MR diff 涉及的**被修改函数体**（不是全量扫描整个文件）
- 从 diff 中识别被修改函数名和位置，对被修改函数进行完整的函数体扫描
- 只报告有明确代码证据的问题
- 忽略 test/mock/stub/diagnose 代码
- 忽略 static inline 工具函数（调用者负责校验）
- 每条缺陷必须标注文件路径、行号、缺陷模式、严重度、根因、修复建议

---

## 3. 指针操作类（共2项）

### 3.1 空指针解引用(入参未判空)

**问题描述**: 函数参数为指针类型但未检查是否为NULL即直接使用。

**检测特征**:
- 指针参数直接访问成员（如param->field）
- 函数入口无判空逻辑
- 访问前未验证指针有效性

**检测关键词**: `*->`, `param`, `ptr`, `ctx`, `arg`

**误报排除**:
- 函数入口已有判空宏(MED_DEV_CHK_PTR_NULL_RET、CHK_PTR_NULL等)
- static inline工具函数（调用者负责校验）
- callback参数由调用者保证非NULL
- UNREFERENCE_PARAM声明的参数
- 已在函数内赋值的参数

**严重度**: 严重

**修复建议**: 函数入口处检查指针参数是否为NULL。

---

### 3.2 空指针解引用(分配后未检查)

**问题描述**: 动态内存分配后未检查返回值是否为空。

**检测特征**:
- malloc/calloc/new返回值直接使用
- 分配后未做NULL检查
- 直接对返回值进行解引用

**检测关键词**: `malloc`, `calloc`, `new`, `alloc`, `WdsMemAlloc`

**误报排除**:
- 已有完善的NULL检查
- fopen失败时句柄为NULL无需释放
- 使用智能指针

**严重度**: 严重

**修复建议**: 分配后立即检查返回值，为空时处理错误。

---

## 4. 资源管理类（共6项）

### 4.1 资源泄漏(分配失败未返回)

**问题描述**: 动态内存分配返回NULL时仅打印日志但未正确返回。

**检测特征**:
- malloc后仅打印日志
- NULL检查后未return
- 继续使用可能为NULL的指针

**检测关键词**: `malloc`, `calloc`, `if == NULL`, `printf`, `LOG`

**误报排除**:
- 成功路径返回已分配资源给调用者
- diagnose/diagnostic代码
- fopen失败句柄为NULL无需释放

**严重度**: 中等

**修复建议**: 分配失败时返回错误码，让调用者处理。

---

### 4.2 资源泄漏(循环内部分失败)

**问题描述**: 循环中为多个对象分配内存，当某个对象分配失败时，之前已成功的对象未被释放。

**检测特征**:
- 循环内malloc/calloc
- 循环内分配失败直接return
- 未记录已分配资源列表

**检测关键词**: `for`, `malloc`, `calloc`, `if == NULL`, `return`

**误报排除**:
- goto cleanup模式
- 有Destroy/Free清理函数
- 使用智能指针容器

**严重度**: 中等

**修复建议**: 分配失败时释放所有已成功分配的对象，或使用goto cleanup模式。

---

### 4.3 资源泄漏(多资源释放不全)

**问题描述**: 函数分配了多个资源，但某些错误路径下未释放全部资源。

**检测特征**:
- 分配了fd和内存多个资源
- 错误路径未全部释放
- 多出口函数

**检测关键词**: `malloc`, `open`, `fopen`, `if`, `goto`, `err`

**误报排除**:
- goto cleanup正确释放
- RAII自动释放

**严重度**: 中等

**修复建议**: 使用统一的清理函数或goto cleanup模式。

---

### 4.4 资源泄漏(句柄未关闭)

**问题描述**: 文件描述符或句柄未在所有路径上关闭。

**检测特征**:
- fopen后未fclose
- open后未close
- 错误路径未关闭句柄

**检测关键词**: `fopen`, `open`, `fclose`, `close`

**误报排除**:
- fopen失败句柄为NULL
- 已使用fcloseall或统一关闭函数

**严重度**: 轻度

**修复建议**: 确保所有代码路径都关闭句柄。

---

### 4.5 资源泄漏(goto err遗漏释放)

**问题描述**: 函数中goto err跳转到错误处理，但err标签后未释放所有已分配资源，遗漏了部分资源的释放。

**检测特征**:
- goto err后只释放了部分资源
- err标签遗漏了fd/close/free等释放调用
- 多资源分配但错误处理不完整

**检测关键词**: `goto`, `err`, `cleanup`, `fail`, `error`, `out`

**误报排除**:
- goto cleanup模式中cleanup正确释放了所有资源的
- 跨函数传递的资源由调用方释放的

**严重度**: 严重

**修复建议**: 在err标签后按分配的逆序释放所有资源，确保每条goto err路径都释放了已分配资源。

---

### 4.6 资源泄漏(引用计数泄漏)

**问题描述**: 引用计数refCount++后，异常分支直接return/break未执行配对的refCount--，导致引用计数无法归零。

**检测特征**:
- refCount++后异常分支return/break未配对--
- 计数操作在循环或条件中不配对

**检测关键词**: `refCount`, `count++`, `count--`, `ref`, `atomic_fetch`

**误报排除**:
- 引用计数在cleanup函数中统一递减的
- 计数操作在锁保护下且退出路径有配对递减的

**严重度**: 严重

**修复建议**: 确保refCount++对应的每条退出路径都有配对的refCount--。
