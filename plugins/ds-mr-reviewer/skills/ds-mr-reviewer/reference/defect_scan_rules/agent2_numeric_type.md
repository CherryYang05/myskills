# 缺陷模式检测规则库 - Agent 2: 数值计算类 + 类型系统类

## 扫描范围与原则

- 聚焦于 MR diff 涉及的**被修改函数体**（不是全量扫描整个文件）
- 从 diff 中识别被修改函数名和位置，对被修改函数进行完整的函数体扫描
- 只报告有明确代码证据的问题
- 忽略 test/mock/stub/diagnose 代码
- 忽略 static inline 工具函数（调用者负责校验）
- 每条缺陷必须标注文件路径、行号、缺陷模式、严重度、根因、修复建议

## 2. 数值计算类（共4项）

### 2.1 整数溢出(sizeof乘法)

**问题描述**: sizeof与数量相乘时可能超过类型上限，导致内存分配不足或计算错误。

**检测特征**:
- malloc/calloc参数中使用sizeof*数量
- 未使用uint64_t中间计算
- 乘积结果可能超过uint32_t上限

**检测关键词**: `sizeof`, `malloc`, `calloc`, `alloc`, `objectNumber`, `count`

**误报排除**:
- 已使用uint64_t中间计算
- 上游已有范围校验
- 变量有注释说明限制范围
- sizeof(char)等原语类型

**严重度**: 中等

**修复建议**: 使用uint64_t进行中间计算，并检查结果是否在合理范围内。

---

### 2.2 整数溢出(无符号加法)

**问题描述**: 无符号整数相加可能发生回绕，导致意料之外的结果。

**检测特征**:
- 两个无符号数相加
- length+offset类型的计算
- 未做溢出检查的累加

**检测关键词**: `uint32_t`, `uint64_t`, `length`, `offset`, `size`, `+`

**误报排除**:
- 64位类型计算
- 已有溢出检查
- 编译期常量计算

**严重度**: 中等

**修复建议**: 使用checked_add或先检查结果是否在合理范围内。

---

### 2.3 整数溢出(ROUND_UP宏)

**问题描述**: ROUND_UP宏在边界情况下可能发生溢出。

**检测特征**:
- ROUND_UP宏定义
- 边界值的上取整计算
- 接近类型上限的值

**检测关键词**: `ROUND_UP`, `ALIGN`, `round_up`

**误报排除**:
- 参数远小于类型上限
- 已有溢出检查

**严重度**: 中等

**修复建议**: 使用安全的上取整实现，检查溢出。

---

### 2.4 整数溢出(循环变量类型)

**问题描述**: 循环变量类型可能不足以容纳最大循环次数。

**检测特征**:
- int类型循环变量用于大循环
- 循环变量在边界处可能溢出

**检测关键词**: `for`, `while`, `int i`, `uint32_t`, `loop`

**误报排除**:
- 循环次数确定且小于INT_MAX
- 使用size_t或uint64_t

**严重度**: 轻度

**修复建议**: 使用足够大的类型存储循环计数。

---

## 7. 类型系统类（共2项）

### 7.1 类型转换错误(单位转换)

**问题描述**: 不同单位之间转换时计算错误，如bytes到KB，us到ms。

**检测特征**:
- latency/delay/time单位混用
- bytes与KB混淆
- 除以1024 vs 1000
- 时间单位混用(毫秒/秒/纳秒)
- 字节与扇区单位不匹配

**检测关键词**: `latency`, `delay`, `time`, `timeout`, `size`, `capacity`, `sector`, `4K`, `MB_TO_BYTE`, `秒`, `毫秒`

**误报排除**:
- 单位转换明确注释
- 使用标准库单位转换函数

**严重度**: 轻度

**修复建议**: 明确标注单位，使用统一的时间/大小类型。

---

### 7.2 类型转换错误(无符号vs有符号)

**问题描述**: 无符号与有符号类型混用可能导致意外行为。

**检测特征**:
- uint32_t与int混用
- size_t与ssize_t混用
- 负值赋值给无符号变量

**检测关键词**: `uint32_t`, `uint64_t`, `int`, `size_t`, `-1`

**误报排除**:
- 显式转换
- 确定不会为负的场景

**严重度**: 轻度

**修复建议**: 避免无符号与有符号混用，必要时进行显式转换。
