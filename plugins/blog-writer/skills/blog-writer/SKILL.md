# Blog Writer

把对话、笔记和实践材料写成离开原始聊天也能读懂的博客。按素材选题，不限定技术领域。默认中文，保留通用英文术语，按读者需要在首次出现时解释。

## 取材与结构

- 先确定读者、文章要解决的问题和范围。主题明确时直接写稿并审校。用户要求先看大纲，或者系列拆分、目标读者或关键事实的不同选择会改变文章主线时，先讨论结构。局部修改沿用已有结构。
- 优先提取原始问题、实际混淆、纠正过程、证据和能独立复算或复现的例子。按知识逻辑重新组织。跨对话只用可访问且相关的素材；证据不足时缩小结论或注明条件。核验关键论断的公开来源、版本、数字和适用范围，内部材料仅供私有取材。
- **知识解析**从读者必需的前置概念进入，顺着问题、假设、机制、推理和结果展开。用最小算例或反例解释真正混淆过的概念。延伸一小步即可，例如机制在哪些条件下变化、实际实现的边界或直接相关的阅读线索。
- **实操教程**交代目标、环境、版本、权限、安装和配置，给出最小可跑路径、预期结果和验证方法。对真实易踩的坑写清现象、原因及修复或恢复步骤。区分亲自验证过的结果、文档记录和示意。代码块注明语言，示意代码与真实项目实现明确区分。
- 复盘或经验文按用户要求组织，保留有据可查的时间线、判断和取舍。可以参考用户认可的同类文章，保留作者的语气和立场，不补写个人经历。

## 智能图与 Markdown 内嵌 HTML

每篇先找出最值得画图的段落，例如流程、结构、状态切换、空间关系或参数变化。图应能回答读者的具体问题。静态关系用流程图、对照图或结构图，调参和逐步演变优先用可操作的演示。纯文字更清楚时无需配图。

- 在 ChatGPT 中，优先使用当前会话可用的 Intelligent UI 或交互式可视化能力预览。已有图就复用数据、标签、初始状态和阅读顺序。有 HTML 源码时转换为正文适用的片段，只有预览时按同一数据重建 HTML。当前环境无法展示预览时，仍完成 Markdown 内嵌图。
- **把实际 HTML 片段写进最终 `.md` 正文，在对应解释附近渲染。** 片段前后留空行，直接写标签。独立 HTML 附件、聊天小组件、图片链接、Mermaid 或 `html` 代码块均不能代替正文里的图。标题、关键值、单位、图例和图注用可阅读的文本表示。
- Halo/ByteMD 正文优先使用 `div`、`p`、`span`、`strong` 或语义表格，必要时用内联 `style` 实现 Flex、换行、间距和边框。继承主题文字颜色，避免固定大宽度及只靠颜色表达。使用实际编辑器预览验证额外标签和样式。正文片段避免 `script`、`iframe`、`style` 标签、原始 SVG、事件属性及外部运行依赖。
- 若原图需要滑块、切换或动画，正文内嵌能独立读懂的静态状态或关键步骤。可额外提供无外部依赖的独立 `.html` 交互版。发布时只链接已验证的公开地址。实际检查窄屏、图中文字、箭头方向、默认值、边界输入和图文一致性。

## 独立读者审稿

1. 先只读正文。从目标读者的起点找缺失的定义、推理跳步、图文冲突、漏写的配置和无法验证的操作。定位具体段落并修订。
2. 再润色。用连续自然段表达完整推理，小标题写具体内容。删掉聊天口吻、重复解释、碎片化小节、程式化转折和口号式收尾。列表用于并列事项，结尾有边界或新的工程含义时再写。中文正文用中文标点，代码、命令、路径和公式里的字符保持原样。
3. 回查版本、数字、单位、条件、引用、代码和图。润色保留事实与不确定性，技术纠错需有依据。行内公式用 `$...$`，独立推导用 `$$...$$`，兼容 Halo。按最终文件预检 HTML、代码块和链接。

## 交付

在当前环境可下载的位置保存 `YYYY-MM-DD-<slug>.md`，其中 slug 用小写英文和连字符。正文包含最终修订和内嵌图，可附独立交互 HTML。默认提供文件链接和简短的修订说明。要求上传 Halo 时，使用可用的发布连接查找真实分类和标签，核对目标后存为草稿并检查主题预览。公开发布按用户对该稿的明确要求执行。没有连接时交付成稿和拟用分类标签。
