# Blog Writer

把对话、笔记和实践材料写成离开原始聊天也能读懂的博客。按素材选题。默认中文，技术术语保留通行英文名称，必要时第一次出现就解释，后文使用同一写法。

## 从对话提炼素材

先提炼素材，再决定文章结构。短对话在起稿前快速过一遍。长对话或混合主题先做一份简短的私有素材表，供写作和审稿回查。

1. **圈定输入。** 从用户这次点名的问题和最新确认的范围出发，回看能解释它的追问、纠正和关键结果。长对话按子问题切段，去掉重复解释、无关支线和无信息的往返。只有当前主题确实依赖旧对话时，才使用可访问的相关片段或用户提供的导出。缺少会改变主结论的材料时，索取具体片段，或缩小成文范围。
2. **标出转折与证据。** 抓住误解被反例推翻、约束改变判断、失败尝试改变下一步、结果经验证这几类转折。每条素材保留要点、支持它的算例、命令及输出、源码版本或原始来源，以及假设与适用条件。必要时记下消息轮次、文件章节或链接，便于回查。把被推翻的说法标为误区，推测和待证事项与已验证结果分开。只保留能解释原因的失败尝试。
3. **选一条主线。** 用一句话写下读者读完能理解、判断或复现什么。原理问题围绕概念和因果，动手任务围绕操作和验证，排障或决策复盘围绕证据如何改变判断。其他问题只有支撑这条主线才纳入。证据只能支撑一个小问题时，就写成一篇短文。
4. **给段落找依据。** 让每个主要章节回答一个读者问题，并关联素材里的证据。把最能支撑核心结论的代码、算例或结果放进正文。教学假设、测试口径和版本限制紧挨结论说明。只把可公开的内容带入成稿。对话里的说法要结合用户材料、实测或公开原始来源核实，未验证的实现、数据和经历留在私有记录。

例如，讨论从「相同键是否允许换序」转到「插入排序遇到相同键时是否继续移动」。正文先定义稳定性，用同一组带身份标签的数据对比 `>` 和 `>=`。早期理解只用于交代容易误解的地方，后续性能闲聊与本文无关。

## 写作与迭代

- 主题明确时直接成稿并审校。用户要先看大纲，或读者、拆篇、关键事实的不同选择会改变主线时，给出简短结构。包括拟用标题、读者问题、各节作用、核心例子和取舍，确认后再写。明确要求直接写时，以可核验的范围起稿。
- **知识解析**按问题、条件、机制、推理和结果推进。先解释后文依赖的概念，沿数据流、状态变化或公式推导展开。用最小算例或反例澄清真正出现的误解。说明结论的边界，补一项直接相关的延伸即可。章节服务于论证。
- **实操教程**交代目标、环境、工具版本、权限、安装和配置。每个关键步骤给出可复制的命令或配置，说明需要填写的参数、正常输出及下一步判断。结尾提供可观察的成功判据。踩坑写清现象、原因、修复及必要的恢复步骤。区分实测、文档说明和示例。
- **复盘与经验**保留有据可查的时间线、当时的判断和取舍。有用户认可的同类文章时，优先参照一两篇的叙述视角、段落密度和术语习惯。保留作者的语气与立场，不补写个人经历。
- 修改标题、某段文字、个别例子或小节时做局部编辑。涉及重组章节或改变主线时，先给简短结构方案，按用户的确认或直接修改指令执行。

### 语言与排版

- 一个自然段推进一个完整论点。小标题描述问题或机制，例如「第一名出现在第 k 个位置时的成功概率」。删除「真正精彩的地方来了」「终极总结」等空泛提示。避免把连贯推理拆成密集的小节、短句或列表。
- 列表用于并列条件和步骤。粗体标出有助于扫读的术语或结论，引用块保留给原话或确有必要的引文。需要收尾时交代适用边界或工程含义，删除重复前文的总结。
- 技术文章用自然、克制的中文。去掉「刚才讨论了」「我来解释」等聊天痕迹。教程可直接使用动作句，复盘可保留能说明判断过程的第一人称。
- 代码块注明语言。真实项目的路径、函数、配置和日志以来源为准。简化代码明确标为示意。中文正文用中文标点，命令、路径、标识符和公式里的字符保持原样。
- Halo/KaTeX 行内公式用 `$...$`，块级用 `$$...$$`。避免 `\(...\)`、`\[...\]` 和渲染器未验证的宏。简单变量留在句子里，例如「设候选人数为 $n$」。长公式、关键等式或完整推导才单独成块。定义公式涉及的符号、单位和条件。

## 智能图与 Markdown 内嵌 HTML

选出一处或几处读者会停下来想象的结构、过程或变化。静态关系用对照图、流程图或结构图，调参和状态变化适合交互。先明确图回答的问题，再决定图形和交互。纯文字更清楚时可省略。

1. **在 ChatGPT 预览。** 在当前会话具备可视化能力且交付场景适用时，优先用 Intelligent UI 或交互式可视化预览。已有图就复用其数据、标签、默认状态和阅读顺序。有 HTML 源码时转成正文片段，只有预览时用同一数据重建 HTML。缺少预览能力时仍完成 Markdown 内嵌图。
2. **写进最终 Markdown。** 在对应段落附近直接写原始 HTML 标签，片段前后留空行。图片链接、独立附件、聊天组件、Mermaid 和带围栏的 HTML 代码块均不能替代正文里的图。图中展示关键值、单位和标签，给箭头和颜色明确的语义。
3. **按目标渲染。** Halo/ByteMD 优先用 `div`、`p`、`span`、`strong` 或语义表格，以少量内联 `style` 做间距、边框和自适应。继承主题文字颜色，关键关系用文字标出。正文避免 `script`、`iframe`、`style` 标签、原始 SVG、事件属性和外部运行依赖。其他标签或样式按实际编辑器预览确认。
4. **保留交互价值。** 如果预览需要滑块、切换或动画，正文内嵌能独立说明问题的默认状态或关键步骤。可补一份无外部依赖的独立 HTML 交互版。有公开托管地址时先验证再链接。

以下是原始 HTML 片段的示意，交付时去掉围栏。示例中箭头与两侧的文字共同表达转换关系。

```html
<div style="display:flex;flex-wrap:wrap;gap:0.5rem;align-items:center">
  <div style="padding:0.5rem;border:1px solid currentColor"><strong>输入</strong> · 原始数据</div>
  <span>→</span>
  <div style="padding:0.5rem;border:1px solid currentColor"><strong>输出</strong> · 转换结果</div>
</div>
```

## 独立读者审稿

1. **只读成稿。** 站在目标读者的起点读全文。定位首次使用却未定义的术语、漏掉的推理、示例和图文冲突、教程缺失的配置与验证步骤。核对开头是否让读者知道在解决什么问题，标题中的承诺是否在正文兑现。直接改对应段落，或收窄标题。
2. **再做语言编辑。** 删除重复解释、模板化转折和口号式收尾。改句子和段落节奏，保留作者有辨识度的表达。润色保留数字、条件、立场和不确定性。
3. **回查素材和最终文件。** 复算关键数字和公式，核对代码、命令、版本、链接和引用。逐图检查箭头方向、默认值、边界输入、窄屏和去掉颜色后是否仍能读懂。检查图是否确实写在正文里，能否在目标编辑器渲染。没有实测的项目如实标明。

## 交付

在当前环境可下载的位置保存 `YYYY-MM-DD-<slug>.md`，slug 用小写英文和连字符。默认提供最终文件链接和简短的修订说明，可附独立交互 HTML。用户要求上传 Halo 时，使用可用的发布连接查找真实分类和标签，核对目标后存为草稿并检查主题预览。公开发布按用户对该稿的明确要求执行。没有连接时交付成稿和拟用分类标签。
