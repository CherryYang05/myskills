# DT用例生成Skill使用指南

## 概述

这个skill专门用于为华为FDSA项目生成DT(动态测试)用例,基于昊天社区的实际经验总结而成。它采用思维链(CoT)方法,将复杂的DT用例开发分解为多个可管理的步骤。

## 适用场景

当你需要为FDSA项目生成DT测试用例时,使用此skill:
- 为FDSA项目生成DT测试用例
- 为大颗粒特性(2w行代码规模)开发测试用例
- 需要使用GTEST框架和MOCKCPP打桩的测试开发
- FDSA的Fusion或Dorado产品线的DT用例开发

## 快速开始

### 基本使用流程

1. **代码理解**: 首先让CodeAgent理解代码结构,生成类图和接口文档
2. **用例场景分析**: 分析测试场景,生成用例列表
3. **DT框架搭建**: 配置构建环境(可选)
4. **识别打桩流程**: 识别需要打桩的接口
5. **用例生成和调试**: 生成具体用例并进行调试

### 示例提示词

```
请帮我为fusion\product\taishan_src\fdsa\src\plugins\libproc_link_info_collect\center\模块生成DT用例。

按照以下步骤进行:
1. 首先理解代码结构,生成类图和接口文档
2. 分析用例场景,生成场景列表
3. 识别需要打桩的接口
4. 生成具体的DT用例代码
```

## 使用技巧

### 1. 步骤化执行

不要一次性要求生成所有代码,应该分步骤执行:
1. 先让AI理解代码
2. 再确认用例场景
3. 最后生成具体代码

### 2. 人工审核

关键步骤需要人工审核:
- 代码理解阶段: 检查接口、结构体、枚举是否准确
- 场景分析阶段: 检查场景是否全面,接口是否正确
- 打桩阶段: 检查打桩粒度是否合理

### 3. 迭代优化

如果生成的代码质量不高,可以:
1. 优化提示词
2. 分批生成用例(一次不超过100个)
3. 提供更多上下文信息

### 4. 调试策略

推荐的调试策略:
1. 先编译通过整个DT框架
2. 再运行全量用例
3. 分析失败原因
4. 集中修复相同类型的问题

## 常见问题

### Q1: AI生成的代码有错误怎么办?

A: 按照以下步骤处理:
1. 检查编译错误,先解决编译问题
2. 运行测试,收集失败信息
3. 分析失败原因,给AI提供具体的错误信息
4. 让AI修复问题

### Q2: AI生成的接口不存在怎么办?

A: 这是常见的幻觉问题,解决方法:
1. 在提示词中强调"必须与现存代码仓的头文件定义完全一致"
2. 让AI自己检查生成的接口是否存在
3. 人工审核接口列表

### Q3: 打桩粒度如何控制?

A: 打桩原则:
1. 资源申请/释放函数: 可以打桩
2. 异步接口: 需要同步化打桩
3. 业务逻辑: 不要打桩
4. 内部函数: 尽量不要打桩

### Q4: 如何提高测试覆盖率?

A: 提高覆盖率的方法:
1. 分析未覆盖的代码路径
2. 补充相应的测试场景
3. 添加边界条件测试
4. 添加异常流程测试

### Q5: 如何处理CoreDump问题?

A: 处理CoreDump:
1. 先人工找到堆栈信息
2. 把堆栈给AI分析
3. 检查指针是否正确初始化
4. 检查数组是否越界
5. 检查打桩函数是否正确

## 最佳实践

### 1. 一次只做一件事

不要让AI同时做多个任务:
- 先让AI把编译调过
- 然后用例以测试套为粒度进行调试
- 逐步解决问题

### 2. 提供准确的上下文

给AI提供准确的代码路径和模块信息:
- 明确代码路径
- 明确模块名称
- 明确依赖关系
- 明确测试框架

### 3. 人工介入关键步骤

在关键步骤人工介入:
- 审核代码理解结果
- 审核用例场景
- 审核打桩策略
- 定位复杂问题

### 4. 保持提示词简洁

提示词应该:
- 简洁明了
- 避免冗长
- 重点突出
- 结构清晰

### 5. 记录有效提示词

将有效的提示词记录下来:
- 形成团队知识库
- 方便后续复用
- 持续优化改进
