# EasyNewOS 仓库维护指南

## 仓库结构

```
EasyNewOS/
├── README.md           # 仓库主文档
├── scripts/            # 脚本目录
├── Fonts/              # 字体文件
├── .vscode/            # VSCode配置
└── 其他配置文件
```

## README 结构规范

### 整体结构

```
# EasyNewOS
简短描述

## Win
### 1. 分类名称
内容描述
链接或命令

### 2. 下一个分类
...

## Linux
### 1. 分类名称
...
```

### 现有结构（保持不变）

**Win 部分：**
1. 激活 Windows 和 Office
2. VSCode(通用)
3. VSCode 插件
4. GCC
5. WSL（含5.1子节）
6. 字体
7. 浏览器插件
8. 系统清理脚本

**Linux 部分：**
1. 换源
2. root 免密登录
3. SSH 及 秘钥登录
4. 常用包的安装
5. oh-my-zsh 安装与配置
6. docker 安装

### 扩展规则

1. **编号规则**：Win 用 "1.", "2.", "3." 连续编号；Linux 用 "1.", "2.", "3." 单独编号
2. **子节编号**：如 "5.1", "5.2" 表示子分类
3. **链接格式**：使用 `[描述](url)` 格式
4. **命令格式**：使用 triple-backtick 代码块，shell 命令加 `shell` 标注
5. **语言**：全程中文

## 写作风格

- 简洁直接，不废话
- 提供外部链接时尽量用可靠的官方文档
- 命令给出完整可复制的版本
- 适当解释"为什么"（如"国内网络限制"）
- 重要提示用 `>` 引用块

## 修改后操作流程

### 1. 提交规范

commit 信息要**简短**，一行即可：
- `增加xxx脚本`
- `更新README说明`
- `添加字体配置`

不要写太详细的 commit message。

### 2. 推送到 GitHub

```bash
git add <changed-files>
git commit -m "简短描述"
git push
```

## 脚本存放规则

- 所有脚本放在 `scripts/` 目录
- 脚本命名：英文或拼音，避免中文文件名（GitHub 显示问题）
- 如果脚本需要文档说明，在 README 对应位置添加说明

## 常用操作

### 添加新分类

在对应系统部分（Win/Linux）末尾，按编号添加：

```markdown
### N. 新分类名称

内容描述...
```

### 修改现有内容

找到对应的 `### N.` 节，直接编辑内容。

### 添加脚本

1. 将脚本放入 `scripts/` 目录
2. 在 README 相关位置添加说明
3. 如果是通用脚本，在两个系统部分都可提及

## 注意事项

1. **不要破坏现有结构**：添加新内容时保持现有编号连续
2. **编码问题**：bat 脚本用 GB2312 编码或英文
3. **中文 commit**：可以用中文，但保持简短
4. **Git 操作**：add → commit → push 三步走
